\begin{minted}[fontsize=\small]{py}
class StellarModel:
    ...
    def compute_m_DUP(self):

        lambda_DUP = np.asarray(self.lambda_DUP)[self.ntpagb :]
        he_core_mass = np.asarray(self.m_core)[self.ntpagb :]
        TP_count = np.asarray(self.TP_count)

        M_DUP = []
        TP_numbers = []

        unique_TPs = np.unique(TP_count)

        for tp in unique_TPs[2:]:  # skip before second pulse

            # indices during this thermal pulse
            pulse_idx = np.where(TP_count == tp)[0]

            if len(pulse_idx) == 0:
                continue

            # maximum lambda during pulse
            lambda_max = np.nanmax(lambda_DUP[pulse_idx])

            previous_tp = tp - 1
            previous_idx = np.where(TP_count == previous_tp)[0]

            if len(previous_idx) == 0:
                continue

            core_previous = np.min(he_core_mass[previous_idx])
            core_current = he_core_mass[pulse_idx[0]]
            delta_core = core_current - core_previous

            if delta_core <= 0:
                continue

            M_DUP.append(lambda_max * delta_core)
            TP_numbers.append(tp)

        return np.array(M_DUP)
    ...
\end{minted}
It is pretty straightforward and uses the following equation,
\begin{equation*}
    \Delta M_\text{DUP} = \lambda \cdot \Delta M_\text{H},
\end{equation*}
where \(\lambda \) is the dredge up efficiency parameter and \(\Delta M_\text{H}\) is the increase in core mass during the preceding interpulse. The additional routines from \citet{rees2024b} give us a good definition of \(\lambda\) which we can use and the implementation of \lstinline[style=output, breaklines=true]|compute_m_DUP()| is mostly determining \(\Delta M_\text{H}\).

The interpulse core mass growth is also computed by the subroutines from \citet{rees2024b}, \emph{but} I have not saved these in the history files, which makes it impossible to use these values for earlier models. I think this solution is sufficient.

\newsection{Envelope Abundances}

As I have shown before the summer break, the surface abundance is not always equal to the envelope abundance, mainly because the surface layers are not\sidenote{at least according to \emph{MESA},} mixed efficiently.

I have implemented some additional routines my \emph{MESA} simulations to compute the average envelope abundance of all computed isotopes.
The implementation ``borrows'' from the implementation of the surface abundance, but using the much larger envelope region to average over.

Below I print my implementation.
\marginfignote{3}{It takes the star object \lstinline[style=output, breaklines=true]|s|, and an isotope index \lstinline[style=output, breaklines=true]|j| as input.}
\marginfignote{20}{It uses the extra variable \texttt{s\%xtra(x\_q\_above)} to determine when the end of the envelope has been reached. Keep in mind that \emph{MESA} starts from the surface and walks inwards. \texttt{s\%xtra(x\_q\_above)} gets saved during \texttt{compute\_M\_conv}.}
\begin{minted}[fontsize=\small,breaklines]{fortran}
real(dp) function envelope_avg_x(s,j)
    use chem_def, only: chem_isos
    type (star_info), pointer :: s
    integer, intent(in) :: j
    real(dp) :: sum_x, sum_dq
    integer :: k
    include 'formats'
    if (j == 0) then
        envelope_avg_x = 0d0
        return
    end if
    sum_x = 0
    sum_dq = 0
    do k = 1, s% nz
        sum_x = sum_x + s% xa(j,k)*s% dq(k)
        sum_dq = sum_dq + s% dq(k)
        if (sum_dq >= s%xtra(x_q_above)) exit
    end do
    envelope_avg_x = sum_x/sum_dq
end function envelope_avg_x
\end{minted}

    def filter(self, **filters):

        for run in self.models:

            keep = True

            for key, values in filters.items():

                if not isinstance(values, (list, tuple, set)):
                    values = {values}

                if run.params[key] not in values:
                    keep = False
                    break

            if keep:
                yield run

    def array(self, value, x, y, **filters):

        xs = self.axes[x]
        ys = self.axes[y]

        arr = np.full((len(xs), len(ys)), np.nan)

        x_index = {np.round(v, 3): i for i, v in enumerate(xs)}
        print(x_index)
        y_index = {np.round(v, 3): i for i, v in enumerate(ys)}

        for run in self.filter(**filters):

            if callable(value):
                z = value(run)
            else:
                z = getattr(run, value)

            if x in ["beta", "delta"]:
                i = x_index[np.round(run.params[x] / (1 - run.params["eps"]), 3)]

                i = x_index[np.round(run.params[x], 3)]

            else:
                j = y_index[np.round(run.params[y], 3)]

            arr[i, j] = z

        return np.asarray(xs), np.asarray(ys), arr

We probably want to look how we obtain the wrong \lstinline[style=output, breaklines=true]|soln(1,1)|.

The scale is computed according to \lstinline[style=output, breaklines=true]|subroutine set_xscale_info(s, nvar, ierr)| in \lstinline[style=output, breaklines=true]|solver_support.f90|.
\nextpage
Here, for normal variables\sidenote{not rotation or abundances}, the scale is determined according to
\begin{minted}[fontsize=\small,breaklines]{fortran}
s% x_scale(i,k) = max(1, abs(s% xh_start(i,k)))
\end{minted}
The values we find for the scale align well with this equation, so it must be the solution to the Newton-Raphson solver that is wrong.

This scheme is represented by repeatedly trying to solve \citep{paxton2010}
\begin{equation*}
    0 = \vec{F}(\vec{y}) = \vec{F}(\vec{y}_{i} + \delta \vec{y}_{i}) = \vec{F} (\vec{y}_{i}) + \l[\dv{\vec{F} }{\vec{y}}\r]_{i} \delta \vec{y}_{i} + \mathcal{O} (\delta \vec{y}_{i}^{2}.
\end{equation*}
Here, \(y_{i} \) is a trial solution, \(\vec{F} (\vec{ y}_{i} ) \) is the residual of the trial solution, \(\delta \vec{y}_{i} \) is the correction to the trial solution and \([\dd{\vec{F} } / \dd{\vec{y} }]_{i} \) is the Jacobian matrix.
The ``solutions'' from MESA are the \(\delta \vec{y}_{i} \)'s, which get scaled by the scale to obtain the changes to the star.

For a single iteration, MESA solves for \(\delta \vec{y} \) in
\begin{equation*}
    J \delta \vec{y} = - \vec{F}(\vec{y} ).
\end{equation*}

To make sure the Newton-Raphson solver is working correctly, I access the Jacobian, correction and the residual.

I then compute the LHS and the RHS of the equation above and test their agreement\sidenote{for the first zone}
.
\begin{minted}[fontsize=\small,breaklines]{py}
lhs = dblk_1.T @ delta_corr_1 + ublk_1.T @ delta_corr_2
rhs = -1 * equ
print(lhs - rhs)
\end{minted}

Nice. The Newton-Raphson solver works! the Problem must occur \emph{before} the solver.

This also means the absurd correction of \(-2.634\) is the \emph{correct} value based on the residuals and the Jacobian.

Let's see how the corrections are constructed, based on the individual components of the Jacobian and the residuals.

From now on, I will only consider the four \lstinline[style=output, breaklines=true]|hydro_vars|. This means I am \emph{excluding} the abundances, which do not seem to impact the first zone anyway.

The Jacobian for the self interaction of the first zone is defined like this:

\begin{equation*}
    \mathbf{J}_{1 \to 1}  = \begin{bmatrix}
        \pdv{y_{\rho} }{\ln \rho } & \pdv{y_{\rho} }{\ln T }& \pdv{y_{\rho} }{\ln R } & \pdv{y_{\rho} }{\ln L }\\
        \pdv{y_{T} }{\ln \rho } & \pdv{y_{T} }{\ln T }& \pdv{y_{T} }{\ln R } & \pdv{y_{T} }{\ln L }\\
        \pdv{y_{R} }{\ln \rho } & \pdv{y_{R} }{\ln T }& \pdv{y_{R} }{\ln R } & \pdv{y_{R} }{\ln L }\\
        \pdv{y_{L} }{\ln \rho } & \pdv{y_{L} }{\ln T }& \pdv{y_{L} }{\ln R } & \pdv{y_{L} }{\ln L }
        \end{bmatrix}_{1\to 1}\hspace{-12pt}, \delta \vec{y}_{1}  = \begin{bmatrix}
    \delta y_{\rho }\\ 
    \delta y_{T }\\ 
    \delta y_{R }\\ 
    \delta y_{L } 
    \end{bmatrix}_{1}\hspace{-4pt}, \vec{F}(\vec{y}_{1}) = \begin{bmatrix}
    F(y_{\rho })\\ 
    F(y_{T })\\ 
    F(y_{R })\\ 
    F(y_{L }) 
    \end{bmatrix}_{1}
\end{equation*}

Now, importantly, this self interaction is \emph{not the only} part that influences the first zone. MESA has couplings to the next and previous cell, where the complete matrix is split in a block diagonal form like this:

\begin{equation*}
    \begin{blockarray}{cccccc}
        & \text{zone 1}  & \text{zone 2} & \text{zone 3} & \text{zone 4}& \text{zone 5} \\
        \begin{block}{r[ccccc]}
          \phantom{\mathbf{A} = }\;\text{zone 1} & D_{1}  & U_{1}  & 0& &  \\
        \phantom{\mathbf{A} = }\;\text{zone 2} & L_{2}  & D_{2}  & U_{2}& 0&   \\
        \mathbf{A}\;\; =\;\; \text{zone 3} & 0 & L_{3}  & D_{3} & U_{3}  & 0 \\
        \phantom{\mathbf{A} = }\;\text{zone 4} &   & 0  & L_{4} & D_{4} & U_{4}  \\
        \phantom{\mathbf{A} = }\;\text{zone 5} &   &   & 0 & L_{5} & D_{5}  \\
      \end{block}
    \end{blockarray}.
\end{equation*}

In the case of zone 1, only \(D_{1} \) and \(U_{1} \) matter\sidenote{For a more general zone \(k\), we have \(L_{k} \), \(D_{k} \) and \(U_{k} \).}.
